# Execute Rebalance

As a user, I want to be able to execute the staged rebalance so that my venue
positions move toward the target portfolio.

## Acceptance Criteria

The checked items record the delivered submission behavior. The reliability
criteria below remain open and must be verified before this story is complete.

- [x] The rebalance action is disabled when there are no staged trades.
- [x] The rebalance action sends only positions that changed relative to the
      loaded exchange state.
- [x] The submitted payload includes account value, cross-account leverage,
      precise mode, and target position weights.
- [x] The UI marks submitted positions as working while orders are in flight.
- [x] Repeated clicks or retries cannot create duplicate submissions: the submit
      handler generates a per-batch `submissionId`, sets a `submitting` flag
      before sending orders, and returns early when either is already set. The
      same `submissionId` propagates with the request so the backend treats a
      retry as the same submission. The transition to working state and the
      clearing of staged trades happen only on the path that owns the guard.
- [x] On success, the app refreshes account and position data from the venue.
- [x] Once the refreshed exchange state matches the target, staged trades clear.
- [x] On failure, the failed position shows the error message and remains
      reviewable.

## Rebalance reliability

- [ ] Every supported execution mode distinguishes confirmed completion, partial
      completion, rejection, and ambiguous order outcomes. Stale venue
      observations cannot produce false success --
      [#92](https://github.com/dataclique/moneymentum/issues/92) and
      [#159](https://github.com/dataclique/moneymentum/issues/159).
- [ ] Each existing trigger has recorded conditions and dispatches against the
      current account and target. Missed, duplicate, stale, and in-flight
      triggers, including account changes, cannot lose or duplicate a rebalance
      -- [#159](https://github.com/dataclique/moneymentum/issues/159).
- [ ] Repeated submissions, reloads, and reconnects preserve recoverable
      execution state. Partial failures remain visible until venue-confirmed
      completion or an explicit blocker --
      [#159](https://github.com/dataclique/moneymentum/issues/159).
- [ ] Full close into cash and position resizing converge to confirmed venue
      state using the connected account's current equity and positions --
      [#91](https://github.com/dataclique/moneymentum/issues/91) and
      [#463](https://github.com/dataclique/moneymentum/issues/463).
- [ ] Tests cover these cases through the actual execution paths, and deployed
      verification follows the existing test-account, funding-cap, and separate
      live-authorization contract --
      [#314](https://github.com/dataclique/moneymentum/issues/314).
